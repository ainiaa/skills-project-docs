# 后台导入预检：拆分需求交付

冻结模拟业务资料，无源码。使用当前 project-docs-product，根据下列已明确规则交付业务主文 prd.md 与独立 prd-traceability.md。业务读者只看主文即可理解规则及结果；测试从追踪找到需求、来源和验收。可以引用本文件。只交付 PRD，不做原型、不画无关页面、不写实现。

本期只定义后台预检规则，无页面或跨角色交接。预检输入为JSON数组，每项为业务键与联系邮箱。数组须1至200项；空、null或非数组拒绝整批，201项拒绝整批，拒绝时无导入任务和写入。业务键是去掉首尾ASCII空格后的非空字符串，区分大小写；同批按规范化后的业务键判重，重复时拒绝整批。邮箱为必填字符串，去掉首尾ASCII空格后非空，其他格式沿已有规则，不在本期发明正则。所有项通过才允许进入原导入流程；这里的“通过”只指预检通过，不等于导入成功，原流程不变。不保存、部分导入、自动重试或新增审批。

保留来源、稳定需求/验收编号和版本关联；主文用中文业务标题，追踪引用主文，不在附件新增条件。生成文档尚未获得当前版本的人工确认。没有其他业务未决；具体接口、表结构和生产兼容性未核实，不阻塞这份目标规则评审。
