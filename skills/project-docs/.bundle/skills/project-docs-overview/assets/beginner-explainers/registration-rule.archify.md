# 为什么我的报名是候补？ {#registration-rule}

确认会占用本场名额，候补暂不占用；名额数据异常时要先核对。

@answer scope="合成报名规则；依据同目录 registration-rule.input.md，仅说明规则，不代表已接入真实报名系统"
@meta locale=zh-CN style=clean

## 看哪两个数字就能理解？ {#decision}

本场最多确认 **3 人**，每次只判断新增 **1 人**。已确认人数指已经占用名额的人数，候补人数不算在内。

| 报名前人数 | 本次结果 | 处理后人数 |
| --- | --- | --- |
| 2 | 确认 | 3 |
| 3 | 候补 | 3 |
| 4（超过上限） | 人工核对，不新增确认 | 4，等待核对纠正 |
| 未提供 | 人工核对，不新增确认 | 未知 |

## 用一次报名怎么理解？ {#example}

小林报名时已有 2 人确认，他确认后就满 3 人。接着小周报名，只能进入候补，已确认人数仍是 3。

## 候补之后一定能参加吗？ {#limits}

@callout level=warning title="仍需确认的规则"
| 材料没有约定候补排序和取消后的递补方式，候补不能承诺最终获得名额。 |
