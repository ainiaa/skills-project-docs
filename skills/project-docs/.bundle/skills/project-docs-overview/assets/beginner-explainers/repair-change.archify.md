# 报修入口拟议变更，会影响我什么？ {#repair-change}

拟议方案把普通报修的纸单入口改为报修表，并提供查询编号；前台派单职责和紧急故障电话渠道继续保留。

@answer scope="合成拟议方案；依据同目录 repair-change.input.md，尚未批准上线，当前仍按现行方式办理"
@meta locale=zh-CN style=clean

## 哪些改变，哪些继续保留？ {#comparison}

| 事项 | 当前方式 | 拟议方式 |
| --- | --- | --- |
| 员工提交普通报修 | 纸单交前台 | 填写报修表，提交后取得编号 |
| 前台处理 | 登记并派单 | 仍负责派单 |
| 员工查询进度 | 材料未说明现行查询方式 | 保留报修编号，按编号查询 |
| 紧急故障 | 原电话渠道 | 保留原电话渠道 |

## 如果方案生效，员工会怎样操作？ {#employee}

@steps id=employee-steps
| submit | 填写报修表 | 使用拟议的新入口提交普通报修。 |
| save | 保留编号 | 提交后取得编号，后续查询时使用。 |
| query | 按编号查询 | 用同一报修编号查看进度。 |

前台继续承担派单工作；紧急故障仍按原电话渠道处理。
