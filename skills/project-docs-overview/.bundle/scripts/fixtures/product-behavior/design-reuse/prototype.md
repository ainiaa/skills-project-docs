# 设备预约：沿用现有设计并交付完整原型

使用 Product Skill 交付精简中文 PRD、完整可点击 HTML 和实际无界面浏览器验收。只用本地模拟数据，不发布、不安装依赖、不启动可见桌面应用，不接入 Figma。开始实现前先编写可执行旅程测试，保留首次运行日志和后续修复日志，不能事后制造红灯。

baseline.html 是本案例提供的合成页面基线，表示应沿用的产品导航、术语、色彩、按钮层级、状态和间距；不是生产系统证据。保留“设备预约 / 我的预约 / 全部预约”的导航关系。基线不包含完整业务实现，不要求像素复刻，也不应复制静态示例成为独立数据。没有源码或其他旧系统资料。

业务规则沿用：借用人选择设备、日期、开始结束时间和理由；理由去除首尾空白后非空，开始早于结束。同设备同日有效预约重叠拒绝，保留全部输入；相邻允许，取消释放时段。创建产生稳定 ID，列表、详情和操作反馈共享同一对象。创建人仅在开始前可取消自己的预约，其他借用人及只读管理员不能代取消，重复取消不改变结果。不做审批、归还或库存模块。固定演示时点 2026-11-02 09:00，统一模拟时区，不用电脑当前时间；允许明确切换演示时钟与模拟身份。

初始“投影仪A”有其他借用人当日 10:00—11:00 的有效预约，另有一条自己的 13:00—14:00 预约。支持另一台设备用于跨设备隔离验证。初始场景还应包含长中文设备名和没有空格的长设备标识，列表至少 12 条模拟记录，不得因此新增库存业务。长名称必须完整可读（可换行或明确展开），不能只剩无法查看的省略号。

需从列表发现任务、创建、处理重叠并修正重试、详情取消、返回列表核对同一 ID；在桌面和 390px 下主操作可发现、无被裁切的关键内容。验证长名称、错误提示展开和多条数据；键盘能完成创建、提交、取消和返回。错误必须可见、输入保留、能执行下一步。相关成功、禁用、错误、已取消状态表达一致，不能只靠颜色区分。

请提供适合评审者的轻量场景说明和可重复演示方式：从交付入口能找到冲突恢复与取消场景，知道起点、角色和预期结果；不要让查看说明自动创建/取消预约或重置已有操作。重置应清楚告知影响并可取消，确认后恢复有说明的初始数据和演示环境。说明不应遮挡业务主操作，不要求做专门的演示平台。

页面布局、组件实现等可逆选择自行决定。业务规则和视觉基线已明确，不用重复访谈；确实发现影响业务的矛盾才询问。PRD 是规则真源，不宣称生产权限、真人验收或已获业务批准。
