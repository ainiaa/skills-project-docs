## 评审先固定哪些口径？ {#review-scope}

@facts
| 判断单位 | 单场活动，每次新增 1 人报名 |
| 配额上限 | 3 个确认名额，候补不计入已确认人数 |
| 正常路径 | 已确认人数少于 3 时确认；等于 3 时记候补 |
| 异常路径 | 已确认人数缺失或超过 3 时先人工核对，不新增确认 |

核对材料中的异常路径后再解释正常判断，不能把缺失人数按 0 处理，也不能把超过上限的状态继续当作普通候补。

## 临界值和异常是否保留一致结果？ {#boundary-cases}

| 报名前人数 | 本次结果 | 处理后人数 |
| --- | --- | --- |
| 2 | 确认 | 3 |
| 3 | 候补 | 3 |
| 4（超过上限） | 人工核对，不新增确认 | 4，等待核对纠正 |
| 未提供 | 人工核对，不新增确认 | 未知 |

人数仅统计已确认者。异常值 4 需要核对纠正，合法配额仍为 3。

## 哪些评审结论还不能定稿？ {#open-decisions}

@callout level=warning title="待业务决定"
| 候补排序、取消后的递补方式尚未约定，不能据此承诺最终名额。 |

材料没有进一步约定负数、非整数等输入的合法性口径，可将其列为补充确认问题；本页不擅自增加处理规则。并发、重复请求及运行效果也没有实现证据，不能从这份业务说明推定。
