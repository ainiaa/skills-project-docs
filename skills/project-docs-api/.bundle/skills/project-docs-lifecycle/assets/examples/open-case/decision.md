# SIM-REG-001：L2 方案比较与分流 v1

作者：Jeff.Liu

> 本页保留 L2 文档分流时点：“本轮不实现”和恢复条件均描述当时。后续模拟实施范围见[范围澄清](simulation-resolution.md)和[当前设计](design-current.md)，当前技术复跑见[案例入口](README.md)；历史决定不充当当前执行结果。

这是模型依据模拟角色规则作出的本轮分流决定，非业务批准。来源：[L0/L1](investigation.md)、[模拟澄清](clarifications-simulated.md)。唯一正式业务主文将为 [prd.md](prd.md)，问题身份不新建。

目标：运营从相同导出快照稳定得到各场已确认有效人数和可回到原记录的待核实明细，组织者仍负责最终座位数。无实测耗时收益；不估 ROI、不承诺减少人工小时。

| 路径 | 适用性与代价 | 本轮决定 |
|---|---|---|
| 不做/仅指导原命令 | 最省变更，但现状 S1=6 是行数，不能按答复排除取消/重复/身份缺失，也无核实名单 | 不满足已明确目标，不选为完成方案 |
| 一次性人工/现有表格核对 | 可以保留原表逐组核实，临时可行；每周多场次、跨渠道重复且有漏核反馈，仍需人工反复执行规则 | 作为过渡替代，不能声称工具不可用；已有可用表格能力未提供 |
| 配置/权限 | 若另有能力可能更省；已给脚本只有 input/session，无改变计数口径开关，不能凭空声称配置即可修复 | 当前无可执行依据；不扩展寻找外部账号 |
| 最小 CLI 改造 | 沿现有 Python 标准库、运营命令和维护人；一次实现规则并输出待核实来源，不建平台 | 推荐并选择文档分支 development；只写需求与设计，本轮不实现 |

选择理由是重复场景与现有可维护命令链，不是“脚本不一致所以必须开发”。如果业务改为一次性或已有工具可满足，可回到人工/配置分流；无不可逆数据变更。

本期仅改变读取快照后的计数与核实输出，不覆盖 CSV、不纠正员工号、不修改报名状态、不建前端/账号/平台、不推通知、不按历史版本回填。重复行保留原始 record_id；跨场次独立计算。研发分支关联需求 SIM-REG-001，PRD draft-1。

决定角色：当前独立模型上下文可选择模拟演练的文档分流；正式业务决定人、研发接收人/排期 unassigned。恢复实施条件：获明确实现授权、指定接收人、核实命令输出消费者兼容。功能、UAT、部署、收益均未执行/未验证。
