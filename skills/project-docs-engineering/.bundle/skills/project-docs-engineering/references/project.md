# 项目接入与维护

作者：Jeff.Liu。PDLC方法改编来源与许可见[声明](../../../references/third-party-notices.md)。

## 扫描、接入与上手

老项目先只读扫描：沿已有图谱定位模块/依赖/API/表，再核对构建声明、源码和现有文档；没有图谱就用现有导航工具，不自动建索引。报告项目布局、技术栈证据、关键流程、可生成的资料及健康问题。问题按阻断/高风险/一般/建议分级，列证据、影响、修复建议和未核实部分；静态发现不能冒充已复现漏洞。

需要接入时在已有目录补源代码支持的实现基线说明、架构/API/数据库资料及索引；复用已有正式文档，覆盖前比较，保留原文。逆向得到的是“当前实现基线”，需要正式PRD时交Product沿唯一主文补齐并取得真实业务确认。扫描本身不改业务代码或默认创建生命周期记录。Overview组织概览和上手，API/Diagram完成专项产物；上手指南含环境、真实构建命令、核心调用链、规范、常见问题与验证状态。

## 初始化、新服务、新应用、模块骨架

区分空目录初始化、现有项目新增单元、已有单元内新增模块。先核对Maven/Gradle模块、workspace声明、同级单元和分层；跟随项目已有位置与框架，不套入新的backend/frontend目录。空项目列出最小职责、依赖、目录与技术栈取舍；用户未选择的新框架/中间件/依赖先确定，不能把脚手架生成当选型授权。

已有服务/应用沿用父构建、命名、配置、测试、异常/鉴权和日志模式；模块骨架放在已有单元中，不顺手加新服务。先写有断言的正常、边界、异常测试，再补最小实现，Converge负责执行闭环。验证构建/测试发现、路由与配置接线；仅文件生成应报告“骨架完成，业务能力待实现”。运行配置不放真实凭据，未授权不启动服务。

## 工程规范

规范沿现有`00_standards`或项目约定就地维护：add创建必要规范，edit比较变更与适用范围，archive保留归档及替代指向，index修复索引和失效链接。规范是持续更新的文档，不为编辑规范创建虚假feature历史。

任务、状态、业务关系及影响沿[Lifecycle协调资料](../../project-docs-lifecycle/references/coordination.md)维护；执行循环和宿主设置沿现有Converge及宿主能力，不在此创建第二套流程。
