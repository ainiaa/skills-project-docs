# 设计与工程配套

作者：Jeff.Liu。PDLC方法改编来源与许可见[声明](../../../references/third-party-notices.md)。

## 技术设计与架构

读取唯一正式PRD、FR/AC、现有代码与约束，区分当前实现和拟议变更。复用现有模式；有实际取舍时比较最小方案的成本、兼容性、风险及回退。设计说明组件职责、调用链、接口/数据模型、异常、权限、并发幂等、事务、可观测性与测试落点，并关联FR/AC。未决业务规则保留待确认；技术设计不代签需求。

架构总览由Overview组织正文、Diagram交付图源；核对服务划分、通信、数据归属、伸缩和可观测性。设计评审检查需求覆盖、前后兼容、可实现性和验证方式；独立文档评审可指出修改建议，用户已授权修订时落实。评审记录区分AI意见和有权人员批准。

## 数据库设计与迁移

从业务实体、状态和查询模式出发，产出ER图、字段类型/可空/默认值、金额与时区口径、主外键/唯一约束、索引及对应查询、规模假设与迁移影响。沿用项目数据库约定，不凭模板引入分库分表。评审写事务、并发、重复请求、锁、删除/保留策略及兼容边界。

迁移generate/diff对照设计与已有脚本生成增量；沿用已有Flyway/Liquibase或其他工具的目录/语义，不改已执行的历史脚本。SQL按用途写静态DDL/DML，注明顺序与可逆性；无工具时交付脚本和执行说明，不擅自引入新依赖。不将Flyway的R重复迁移前缀当作撤销；U支持取决于现有版本和许可，不假设都能执行。

status优先读已有迁移工具的真实输出/历史；只有脚本时只能说“文件已准备”，不能推断数据库已执行。up/down请求在这里准备待执行/撤销清单、备份与数据风险说明；只有实际执行证据才能登记已执行/已回滚。生成或展示SQL不授权连库执行，逆向DDL不能保证恢复已删除数据。隔离数据库执行验收需实际项目/环境支持。

## UI实现与API Mock

UI交互、四态、视觉系统和产品原型由[Product UI设计](../../project-docs-product/references/ui-design.md)维护；Engineering核对前端组件、接口、响应式及无障碍实现和测试落点，不重写业务交互规则。

Mock基于已核对的API契约，覆盖正常、边界、空列表、分页、非法参数和错误响应，字段/枚举与接口一致，使用有业务含义的合成数据。沿用项目已有mock机制与目录，写启用/停用方法，校验样例schema及前端调用；不引入新Mock依赖，不把Mock联调绿灯当真实服务验证。

## 国际化

先核对现有locale框架和默认语言，只抽用户可见硬编码文案，生成稳定有语义的key；保持占位符、复数、日期/金额格式与回退。按模块更新资源与引用，不翻译代码标识、外部协议或日志key。先补缺key、占位符不匹配、未知locale/回退和正常展示测试，再替换文案；机器翻译注明待人工语言审校。已有项目未采用国际化框架时先明确方案与依赖，不能为抽文案擅自重构应用。

技术设计产物可直接按以上内容填写；不强制套用有示例业务参数的上游模板。交接附来源版本、变更文件、设计决定、未决与测试计划，代码实现仍交Converge，不由文档状态触发执行。
