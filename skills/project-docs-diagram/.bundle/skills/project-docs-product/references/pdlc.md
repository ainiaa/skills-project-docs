# 可选 PDLC 交接

只在用户选择 PDLC 协作时读取。产品 PRD、原型、评审与版本修订独立工作，缺少 pdlc-prd 不阻塞。不要因为发现安装就自动调用，不把原生阶段推进当成人工产品确认。

## 只读诊断

在现有 `product_dependencies.py --skill-root <实际上游目录>` 后按需追加 `--pdlc-root <实际 PDLC 目录>`，可重复。必需探索能力的 `ready` 与可选 `pdlc` 分开：`available` 只证明入口、模板及内容身份，`compatibility=handoff_only` 表示未验证原生接管/修订契约；`missing/incomplete/ambiguous` 分别报告缺失、损坏或遮蔽。没有显式目录不扫描全局，不安装或升级。诊断不调用上游、不读取或改写功能状态，不分配 ID；宿主可见性和模型行为仍未证明。

## 单一 PRD 与身份

先确定一个正式 PRD 路径和当前产品版本。已有功能保留原功能 ID、FR/AC、人工内容及合法确认记录；文档修订不产生新功能。对比稿与历史快照注明用途，不维护两份可独立变化的正式 PRD。无功能身份时暂不分配 PDLC ID，独立交付无需伪造 PDLC 追溯头。

用户选择进入原生流程时，交接同一正式 PRD、已有身份（若有）、当前版本、来源、已决/未决事项、差异、FR/AC、原型与实际验证证据。上游可在显式要求时提供模板或自检参考，但不重复主持需求访谈。

## 能力与失败边界

当前适配不猜测 `--adopt` 等参数，也不调用会另建 ID/PRD 的入口来冒充原位接管。仅在原生契约实际支持且核验身份、文档路径、重复调用、阶段回退和失败语义后才执行相应交接；该执行适配尚未实现。当前输出完整产品交付和人工可执行的原生交接建议，明确“工作流未接入”，不谎称 PDLC 阶段成功。

PDLC 状态只归原生机制维护。本 Skill 不写 `docs/.pdlc-state`，不复制状态机、不通过修订 PRD 回退已评审或已发布阶段。接入失败保留有效产品交付物，分开报告产品结果与 PDLC 结果；建议下一步不自动进入技术设计、实施或发布。

## 可选上游任务（本轮不实施）

在 PDLC 仓库单独增加已有功能 ID、PRD 路径和修订身份的接管契约，并明确重复调用、阶段保护、失败与回执语义。上游通过自身测试后，再实现对应执行适配；不是本 Skill 独立交付的依赖。
