# 产品行为评测

评测真实成品的决定与使用结果，不以关键词、编号或结构通过判定语义优秀。按本次变化选择少量相关样本；不默认重跑全部，也不以有限样本承诺稳定成功率。

评审标准直接引用权威约定：[来源、确认及恢复走读](workflow.md)、[正文、角色阅读及交付](reading-and-change.md)、[完整原型及旅程](prototype.md)。本文只规定取样与证据；不重复维护另一份产品规范。确定性测试保护文件关联、版本与报告契约，内容效果由实际成品复核，不能用固定句子是否出现代替。

## 样本与观察

| 能力 | 输入或扰动 | 检查实际结果 |
|---|---|---|
| 需求保留 | 资料充分时直接整理，局部修改只聚焦多个独立功能中的一个；或删除一个仍有效约定 | 找到遗漏，能定位主文及验收，撤出须有依据；不复制无关功能 |
| 连续修订与场景交接 | 复杂业务先生成，再合并范围、增加只读展示；另选简单文案对照 | 背景、原场景、范围边界和候选在每轮均保留；顺序变体有具体字段及余额；展示沿返回/导出/验收联动；简单需求不变长，不增加审批 |
| 确认边界 | 口径冲突、标注修订旧口径、局部确认、未回复或暂停恢复 | 保留真决定，不重问；不扩大全文批准；只推进独立部分 |
| 澄清时机与分类 | 审批阈值未定；“200字”口径含糊；同规则已明确UTF-16码元但实现未核实、文档未签核；用户明确暂缓阈值的讨论草稿 | 前两例先问关键业务问题，不把新发现的歧义推给研发；明确口径例直接整理并分清技术待核实与待批准；明确暂缓例不催问、不自选阈值，受影响验收保持未完成；发现其他关键问题可提问，但仍交付独立部分 |
| 评审与继承口径 | 生成和评审均明确沿用已有计数约定；另给正文与验收冲突、没有来源优先级的只读评审 | 沿用口径不重问，不因实现未核实或待签核重新访谈；冲突先问业务，不按正文或验收自行选边；仍交付独立问题意见，仅评审不改写PRD |
| 混合与异常恢复 | 已有有效结果＋来源故障、一方完整一方缺失、局部冲突、结果不明 | 正确采用优先级与读写集合；从反馈能找到责任/入口/恢复条件，缺口如实保留 |
| 增量与无源码 | 同业务分别提供源码、无代码截图/口述；新产品无基线 | 目标业务规则一致，差异仅在事实证据；不虚构源码、旧页面或后台能力 |
| 精简与计算 | 简单文案变更；另选计算/分摊需求 | 前者短说明与必要验收即可，后者按需给能复算的单位、基数、公式、输出和候选假设 |
| 图文与原型 | 页面状态改变，随后返回其他页面或处理下一组 | 图、规则、页面及验收采用同一对象和影响边界；完整原型才验证共享状态/导航 |
| 确认继承 | 单文件与显式文件对的版本链，规则/AC/来源改变及未冻结引用 | 未变旧记录保留，受影响项重确认；错版、重复、逃逸、隐藏声明不得通过 |

## 如何执行

生成者使用独立上下文，只读本次输入、当前Skill及必要原始资料，不给oracle、预期答案、旧诊断或其他样本成品；无源码例不得搜索真实仓库补资料。只读评审读取实际文件与必要图片，按workflow.md的覆盖核对和结果走读推导，不能把生成者的自述当证据。

保留输入、Skill/所用资源身份、原始成品与实际完成回执；修订后另记版本/哈希，不把控制器改稿或一次定点修订算成另一次独立成功。修复后仅复测受影响样本，仍有缺口就报告未覆盖；不放宽断言或改冻结输入凑通过。技能身份改变后旧结果仅证明旧版本。

报告的skillIdentity同时绑定PRD与原型起稿模板、当前Product校验/浏览器/评测/依赖诊断代码及解析依赖文件；这些内容改变后须重新执行受影响观察，不能只更新报告哈希。外部浏览器、运行环境及真实业务系统仍以实际执行记录说明，文件身份不证明它们已验证。

真实长会话用原始资料和冻结源码，按时间逐条释放真实用户输入，上一轮实际答复及成品落盘后才追加下一条；原助手答案、后续成稿与评判清单不交生成者。历史未提交工作区无法还原时标明采用当前快照，不能把代码后续修复归功Skill。反馈若引用旧助手的方案、页数或错误，按新生成稿实际判断，已满足不计新返工；新增业务决定不追罚早期。另记风险类别、具体反例和数值差额各在何时主动发现，不能把最后用户输入中自带的问题倒算成自主发现。必要私有材料留本地评测包，不装入公开夹具。

真人试读另由实际业务、研发、测试独立复述规则、设计阻塞和验收，记录重复提问及返工；无人参与时保持未验证，不用模型代替岗位批准，不报告未观测的节省比例。当前真人试点暂不开展。

## 优化效果对照

改技能前冻结旧版、同一业务输入及评判依据，选本轮受影响任务和一个未改能力的回归对照；另选未参与修订的输入检查泛化。新旧版使用相同任务、资料、工具边界和执行条件，各在独立上下文完成；续轮只在各自原上下文按顺序追加，不提前泄露。每轮成品与执行回执分开保留，评判者只见匿名版本和原始输入/标准，不见新旧身份、修改意图或生成者自评分。

逐项给结论及成品位置，检查实质遗漏、错误推荐、越界、修订丢失与反复提问；校验器通过不能代替这些判断。评判者还要检查标准是否有区分度：明显错误成品也能通过、或两版本都能轻易完成时，该题不能证明增益。平局和证据不足如实记录，不为显示提升追加规则或改变输入；针对真实失败最多做一批定点修复并重验受影响项，无新证据就结束本轮，不无限打磨。

只报告可核实的交付耗时、提问和工具观测；没有宿主用量/执行证据时，token、工具节省及执行成本写不可用，模型自报不能补造。单次对照只是方向性观察，不承诺稳定收益；需要更强结论时，对新旧版做独立复测并报告失败和波动。复用已有评审文件/报告，不新增运行平台；真人试读另记未验证，不设为模型可代签的门槛。

## 复用现有样本与工具

- `scripts/fixtures/product-behavior/cases.json`：十三个下一动作、确认及范围观察样本，包含四个澄清时机对照和三个生成／评审／继承口径对照；新增样本记录 `businessUndecided`，相关样本另记录 `technicalUnverified` 和 `approvalPending`，旧六例观察字段不变。只读评审例另记录 `writePrd=false`，冲突例的 `reviewFindings` 记录冲突及独立文案问题，不能只问问题而漏交独立意见。journey/uncovered使用同一业务阶段词典，保存反馈不等于最终业务结果。观察字段须由实际回复和成品复核填写，声明本身不证明语义。
- `artifact-cases.json`及`revision-baseline.md`：实际PRD成品、历史影响及未变确认；`multi-input/cases.json`：同业务多资料条件及冲突的独立试验。输入路径相对上述fixtures目录，不改旧样本含义。
- `lean-split/cases.json`：轻量文案、阈值规则及显式主文/追踪拆分的定向成品试验；每次只选本轮受影响样本，另保留输入、两个模板及必要引用的身份，独立复核主文能否读懂、附件有无新增规则、链接及版本是否一致。不冒充旧全量样本门禁通过。
- `delivery-closure/cases.json`：独立交付的来源可移交性及修订后的当前评审／校验回执；使用独立上下文生成，默认资源校验核对前者，实际文件及最新回执核对后者，保留修复前后结果。
- `revision-handoff/cases.json`：复杂场景、连续局部修订及轻量对照。生成者只读input，不读checks；修订例按顺序在同一上下文追加continuations，保留每轮成品，不能一次提前给齐后续要求。复核者读取原始输入、每轮成品和本例checks，检查具体读者答案、位置及反例，不能用生成者自评替代。确定性测试只证明输入可读取、续轮独立，不证明正文语义；有限成品试验也不接入或冒充十三例完整发布观察通过。
- `stage-routing/cases.json`：评审、整理/续轮、探索三类独立输入，criteria仅供评判者读取。用于上述新旧版对照，探索例保留真实依赖检查，另外两例检查资料充分时能否直接交付；readerTrial=not_run保留真人缺口。确定性测试只核输入/续轮/评判文件可读取且分离，不把样例存在当作语义通过或全量发布观察。
- `product_behavior_eval.py --artifacts <report.json>`检查成品报告、文件身份及冻结输入信号；`PRODUCT_ARTIFACT_REPORT`和`PRODUCT_BEHAVIOR_REPORT`使相应pytest使用真实报告，缺失则明确跳过。信号和哈希不证明语义、模型作者或批准。
- 成品报告每个样本的 `prd` 为 `{path,sha256}`；拆分时显式增加同结构 `tracking`。两文件联合检查版本、资源及冻结信号，追踪也要校验哈希；旧单文件报告继续有效。历史修订仍须满足冻结输入的保留/变更要求，拆分不自动授予确认继承。报告资源必须在其允许目录内，不隐式放宽来源路径。

发布前运行组合检查：`python3 scripts/product_behavior_eval.py --release --report <behavior.json> --artifacts <artifacts.json>`。两份报告必须同时通过当前身份与冻结样本检查；缺失返回 `uncovered`，非法或陈旧返回 `invalid`，均为非零退出码。保留报告生成时的上游目录，在同一执行环境验证；不搬移报告后重写其依赖身份。测试夹具只验证门禁行为，不作为真实模型观察。普通 CI 执行 `.coveragerc` 声明的四个 Product 模块 90% 行覆盖率门槛，仍不代表模型、真人、浏览器或整个仓库的质量通过。
- PRD结构用`validate_product_doc.py`；完整原型复用`product_bundle.py`、`product_browser.mjs`及退款/资源权限申请示例的自有旅程。PRD插图、某样例旅程与任意新完整原型分别报告，不互相冒充覆盖。

不为普通文档建立打分、状态机或新工具链。报告只列实际样本、次数、发现、修订与剩余缺口；测试、模型复核、浏览器及真人结果分开记录。
