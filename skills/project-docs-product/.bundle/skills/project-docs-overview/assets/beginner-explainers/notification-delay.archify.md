# 订单已受理，为什么还没收到通知？ {#notification-delay}

受理订单与送达通知是不同步骤。现有材料能说明记录状态，尚不能确认通知延迟的根因。

@answer scope="合成客服材料；依据同目录 notification-delay.input.md，未查询真实日志、未执行重发或修改订单"
@meta locale=zh-CN style=clean

## 哪个环节还缺证据？ {#mechanism}

订单受理、通知发送、用户收到是不同环节。受理记录只说明前一个环节，判断后面的情况还需日志和回执。

@workflow id=notice-flow title="证据核对思路，不是本次执行轨迹"
| accept | 受理记录 | external |
| delivery | 日志与回执 | external |
| accept > delivery | 仍需核对 |

## 目前知道什么，哪些还不知道？ {#evidence}

| 材料 | 能说明什么 | 尚不能证明什么 |
| --- | --- | --- |
| 订单记录：已受理 | 系统记录了受理状态 | 不能据此认定通知已送达 |
| 通知记录：待发送 | 记录仍在等待发送状态 | 不能替代发送日志和实际执行证据 |
| 用户反馈：未收到 | 用户报告了未收到的现象 | 不能单凭反馈断定网络故障 |

@callout level=warning title="原因仍待核实"
| 材料没有发送日志和送达回执，网络故障或服务宕机只能作为待核假设，不能写成已确认根因。 |

## 客服现在可以怎么说明？ {#next}

说明订单记录为已受理，通知问题不会自动取消该订单；建议核对发送任务、日志和送达回执，再判断处理办法。此次解释不承诺送达时间或重发成功。
