## 隔离验证

在集合根目录运行（标准库 Python，无需打开桌面程序或浏览器）：

```bash
PYTHONPATH=scripts python3 -m unittest test_lifecycle_record test_lifecycle_delivery
PYTHONPATH=scripts python3 -m unittest test_install test_update
python3 scripts/lifecycle_record.py --record skills/project-docs-lifecycle/assets/lifecycle-record.json
```

[订单状态合成案例](../assets/examples/order-status/scenario.md) 保留痛点、需求、AC→测试映射、设计、实现、构建、测试、隔离执行及交接引用；[案例记录](../assets/examples/order-status/lifecycle-record.json) 为回放输入，不能作为本次真实执行回执。测试在临时目录实际运行单元测试、以 SHA-256 标识构建、将同一制品复制到隔离目录并在新进程冒烟，注入失败、恢复后核验，再验证需求变更和同 ID 接续。构建、测试和部署冒烟的技术证据引用在临时目录内实际解析到构建摘要、测试输出与冒烟日志，避免把脚本源码当作执行回执。临时目录自动清理，测试 stdout 是本次自动验证结果；如需长期审计，实际试点应另按项目规则保留这些运行产物。[多分支记录](../assets/examples/order-status/branched-record.json) 额外覆盖同一问题关联多个需求、多个工作项共享构建、试点成功但全量阻塞、效果待观察；该文件仅做结构模拟，不代表功能或发布实际完成。

业务决定、UAT、发布批准和 L10 交接在此案例中是**模拟输入**；真实的只有本地测试/制品执行及恢复检查。业务效果、生产部署、数据补偿、真实平台访问控制、模型实际使用本 Skill 的遵循程度、跨 AI 交接及自动续跑均未由此测试证明。不把完整结构链路通过写成真实业务全生命周期验收通过。

## 完整模拟业务实跑：维修进度查询

[原始业务输入](../assets/examples/repair-tracker/input.md) → [问题受理](../assets/examples/repair-tracker/problem-intake.md) → [调查分析](../assets/examples/repair-tracker/investigation.md) → [方案分流](../assets/examples/repair-tracker/decision.md) → [唯一 PRD](../assets/examples/repair-tracker/prd.md) → [技术设计](../assets/examples/repair-tracker/design.md) → [逐 AC 测试](../assets/examples/repair-tracker/test_app.py) 和 [应用代码](../assets/examples/repair-tracker/app.py)。前置三份分析是在用户指出不足后依据原模拟输入补录，文件保留补录说明；原始输入及旧演练回执不改写。复跑会分别引用这些产物，缺少或为空时在技术执行前停止。本案例由实际会话加载 Lifecycle 和 Product 后组织需求、测试先行开发并执行；[产研走读](../assets/examples/repair-tracker/review.md) 保留本次模型检查边界，不伪称独立评审或业务批准。

复跑已编写案例的技术链路：

```bash
python3 scripts/run_lifecycle_pilot.py --output <尚不存在的交付目录>
PYTHONPATH=scripts python3 -m unittest test_lifecycle_pilot
```

运行器保留输入、代码、PRD 校验、缺实现的红灯回放、单元测试、构建摘要、真实回环 HTTP 回执、源故障503、同构建恢复、记录历史、需求版本变化的待复核反例和完整性清单；所有服务在结束时停止。输出目录不得覆盖。维修案例的单测回执同时保存实际执行数、失败、错误和跳过数；七项业务用例必须实际执行，空测试、跳过或预期失败不能凭退出码0生成模拟验收通过。缺失最终证据时不写成功报告；启动回执暂未写完整时等待，HTTP 异常时保留失败状态并停止进程。`result.json` 最后写入并绑定 manifest 摘要，不能从空检查列表推断通过。

该命令只复跑已写好的技术案例，不重新调用模型生成业务方案。真实 HTTP 执行不是仅跑结构脚本，但仍限合成身份/内存数据和本机隔离环境；没有真实 UI、认证平台、业务 UAT、生产批准或业务收益验证。业务效果维持待观察。一次当前会话案例也不能证明其他业务、角色交接或独立模型样本的稳定成功率。

## 内容质量、逐 AC 追踪与交接边界

[质量与追踪契约](quality-and-trace.md)要求实际阅读阶段内容、保留判断依据及缺口。自动trace只核对声明的自动化子集；人工AC保留在唯一PRD并引用真实场景、结果和确认来源，不能填假的unittest回执或从自动化结果推定业务批准。

默认tested交接把当前执行回执关联到记录中的明确L6 executed证据，并核对产物与证据的构建/环境/范围；错绑、缺失、L6未完成、质量/测试失败或陈旧依赖都不能通过。显式transfer只允许资料转交，保留gaps/needs_review及quality_ready/tests_ready；支持人工资料、失败修复或效果待观察，没有自动trace时tests_ready=null。不允许借transfer绕过身份、摘要、L6关联或上下文错误。

```sh
PYTHONPATH=scripts python3 -B -m unittest test_lifecycle_quality test_lifecycle_handoff
python3 scripts/lifecycle_quality.py handoff --root <实际资料包> --contract handoff.json
python3 scripts/lifecycle_quality.py handoff --root <实际资料包> --contract handoff.json --purpose transfer
```

CI用当前采集器真实执行小型临时fixture再建包，并在独立进程中验证、复制、CAS更新，覆盖错绑、缺字段、共享回执的多分支冲突、跳过、人工资料、失败与待观察等正反例。[业务案例](../assets/examples/open-case/README.md)另用当前工具在临时目录真实重跑17项测试及FR/AC映射。CI没有历史成功回执或历史工具源码依赖；所有写入和缓存都限测试工作副本，冻结输入不变。

原独立模型实跑的前置调查/模拟答复、两轮TDD、只读修复、83文件冻结检查点及工具版本已迁入[审计归档](../../../audits/lifecycle/README.md)，原88文件逐项摘要验证保留，当前Skill资源不再含两套运行工具副本。此前独立接续曾在本地真实执行模拟UAT、隔离发布、故障恢复与支持复跑，CAS由revision2至7，L10效果保持待观察；这些是历史结果，不当作本次新验证或模型稳定成功率证据。未验证真人批准、生产、真实效果或桌面聊天自动切换。

当前确定性回归不等于模型试读，也不证明角色能在真实组织中完成验收；旧维修运行器仍是原有技术回放，其计数门禁不代表逐AC语义审查。更多模型/业务行为验证应针对真实缺口，避免每次改工具都重复完整历史演练。

## 真实试点的行为验收

确定真实项目与权限后，分别执行并留输入、当前版本、实际成品/结果、环境、执行人和时间：

| 请求或失败输入 | 应观察的结果 |
|---|---|
| 单独要求 PRD 或图 | 使用相应能力；不创建整套生命周期记录，不自动编码 |
| 新需求完整推进 | 保留问题原话和身份，复用专业能力，实际完成授权代码/测试；逐项核查 L0–L10 及证据 |
| 已有 FR/PRD 中途接入 | 沿用 ID、唯一主文和有效确认，无重复访谈/身份/外部动作 |
| 业务无 AI / 有 AI | 原始来源、草稿与确认版分开；人员职责和访问边界不变 |
| 草稿变更或关键业务未决 | 只阻塞受影响定稿/实现；继续独立取证和准备，二次确认绑定新版本 |
| 非研发、多个分支或分批发布 | 各自记录结果及 Owner；未完成分支不能被成功分支覆盖 |
| 缺失/陈旧/冲突/越权证据或工具失败 | 保留有效结果，报告缺口与恢复条件，不声称门禁通过 |
| 资料中包含执行指令、接收方无权限 | 不改变授权、不越权共享；用获授权渠道交接 |
| 部署/冒烟失败 | 停止扩大、按授权预案恢复，复核业务/数据，再决定重新发布 |

以上是真实环境与更多独立模型样本仍需执行的验收场景；维修案例与新案例分别提供当前会话回放、一次独立模拟前向试跑及接续，不能视为全矩阵已通过的模型评测。安装回归与记录一致性测试也不能证明这些行为。真实工单/审批/部署集成、完整 25 实体模型及 PDLC 接管须待明确目标后单独实现与验收；本切片不安装新依赖或平台。
