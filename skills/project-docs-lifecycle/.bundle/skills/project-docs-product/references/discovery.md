# 产品发现与投入决定

作者：Jeff.Liu

仅在用户需要判断问题是否值得投入、多个机会如何取舍，或研究资料需要综合时加载。
规则明确的增量需求、Bug 和定点修订直接走已有路径，不强制访谈、实验、打分或新建发现文档。
目标含糊时仍按工作流检查并使用当前主导探索能力；本文提供发现产物与交接约定，不另开第二个主持流程。

## 从证据走到决定

1. **明确要支持的决定。** 谁遇到什么问题、当前怎么处理、投入决定最迟何时需要、能观察到什么变化。
   先读取已有资料和有效决定，不重复索取已有答案。
2. **综合资料并保留反证。** 将访谈、工单、观察或数据按机会归组。每条重要结论保留来源位置、时间、适用人群及限制；
   区分用户原话、实际行为、解释和假设。多条记录来自同一用户/同一事件时不当作独立样本，不把模型生成的人物当真实访谈。
3. **比较机会与候选方向。** 从期望结果连接用户机会、候选处理方式及关键假设。包括沿用已有能力、流程/配置调整和不做研发。
   有多个实际可行方向时比较取舍；已明确的方向不为凑数量重新开放。
4. **验证最危险的假设。** 按当前决定选择价值、可用性、可行性或持续运营方面的关键未知，说明哪种反证会改变选择。
   每个必要实验写假设、对象/方法、观察指标、期限、继续/调整/停止条件及负责人；阈值没有依据时作为待决定建议，不能写成用户已批准。
   实验可以是一次任务观察、现有报表核对或明确标模拟的原型；不默认要求开发或接触真实用户。
5. **形成投入决定。** 给出继续、调整、暂缓或停止及理由；资料不足就说明缺少哪项决定证据、谁补充和哪些独立工作可继续。
   未回复不等于同意，无法验证不能写成失败，实验通过也不等于产品已实现。

## 多个需求的优先级

先看既有战略、约束、依赖、风险和可投入容量；使用已有排序方式。
只有 Reach、Impact、Confidence、Effort 的口径和来源可说明时才按需计算 RICE：
`Reach × Impact × Confidence / Effort`。统一时间窗口和工作量单位，Confidence 明确使用 0–1，Effort 必须大于零；
输入未知就保留未知或用有依据的范围分析，不将模型猜测填成精确分数。分数不替代必须先做的依赖、合规要求或业务决定。
资料不适合量化时，直接给推荐顺序及理由，不为输出排行榜补造数字。

## 最小交付与 PRD 交接

复用现有研究或问题分析材料；确需独立产物时，可使用[发现决定提纲](../assets/discovery-brief.md)，删掉不适用部分。
让读者直接找到：要做的决定、证据和反证、候选取舍、关键未知、验证结果/未执行项以及下一步。
模拟资料、建议和有权人员决定分别标明。原始业务资料留在获授权位置，不为演示复制到公开夹具。

进入 PRD 时引用同一问题/需求身份及来源，把已决定的目标、范围、约束、规则和可观察结果交给正式主文。
发现材料不维护另一份可独立变化的 FR/AC；后续业务规则仍由唯一正式 PRD 维护。新证据推翻假设时明确影响，保留旧决定历史。
用户只要研究或决定时到此交付，不自动进入实现或发布。

## 内容验收

从原始输入逐项核对重要结论能否追到真实来源，是否存在被忽略的反证、重复样本或把相关性当因果。
用一个会改变决定的反例检查建议，检查实验是否真的能区分候选而非只得到赞同。
区分“计划了实验”“实际执行并观察”“有权人员决定”；数据或观察期不足保持未验证。
文件、链接与模板检查只证明资料可用，不能证明模型正确综合了研究或实际节省了成本。
