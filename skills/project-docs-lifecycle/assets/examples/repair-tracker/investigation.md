# L1 现状调查与问题分析：维修进度获取

作者：Jeff.Liu｜关联身份：SIM-REPAIR-001｜文档修订：补录-1

**补录说明：**2026-10-31，根据[受理单](problem-intake.md)与[原始模拟输入 v1](input.md)补充分析。未开展新的访谈、现网检查或数据统计；下面明确区分模拟设定、反馈、推导及真实项目待核实项。

## 当前业务链与断点

可从模拟原话直接得到的链路为：员工提交报修 → 等待 → 不清楚进度及下一步 → 再次询问行政。行政从什么系统查、回复需要多久、员工是否已有查询入口，原话未提供。

拟改善的是等待阶段的信息获取。查询接口是原模拟案例预先选定的方案；判断真实组织应采用何种方案，还需要调查下列候选原因。

## 证据与判断边界

| 编号 | 资料与陈述 | 分类 | 能支持的判断与限制 |
|---|---|---|---|
| E1 | 员工反馈不知道进度、反复询问 | 模拟业务反馈 | 支持受理信息获取问题；不证明现网没有查询功能 |
| E2 | 行政要求只能看本人、查询不能修改工单 | 模拟业务规则 | 可用于本次演练验收；真实数据权限尚未核实 |
| E3 | R-100/R-200 及其归属、状态和下一步 | 合成样本设定 | 可复演正常、越权与无数据；不证明真实数据源可用或准确 |
| E4 | 本案例无历史系统，D1 选择只读接口 | 原模拟范围设定 | 可建立独立试验；不等于已调查真实组织的旧系统 |
| E5 | 询问人数、频次、响应耗时、处理成本 | 未取得的数据 | 无法计算真实收益、优先级或投入产出 |

## 候选原因与核实方法

| 候选原因 | 如何核实 | 若成立，优先分流 |
|---|---|---|
| 已有入口但员工不知道如何使用 | 查现有操作资料、入口可达性并请用户复演 | 操作指导、知识交接 |
| 已有查询能力但权限或配置不正确 | 对照规则检查实际角色、授权和配置 | 权限或配置处理 |
| 数据缺失或维修状态不及时 | 核对工单来源、更新职责和具体样本 | 数据质量、流程职责处理 |
| 无可用查询能力，且有可信数据可供查询 | 结合代码/接口/产品资料及业务确认取证 | 研发需求 |

以上均为调查分支，未被标成真实已确认根因。真实调查中发现任一非研发分支足以解决问题时，应记录处理结果，而不是默认开发。

## 目标与待补信息

模拟目标明确为本人只读查询、明确的下一步和可恢复的失败反馈，详情交由[方案比较与分流决定](decision.md)承接。

真实试点仍需补：已有入口及能力、数据来源和更新责任、实际身份与权限、询问频次及耗时基线、试点用户范围、业务负责人。没有这些证据，不声称已完成真实根因确认、价值评估或收益验证。指标可先观察“每个工单发生的进度询问次数”和“获得进度所需时间”，定义口径、观察期与目标值由真实业务负责人决定。
