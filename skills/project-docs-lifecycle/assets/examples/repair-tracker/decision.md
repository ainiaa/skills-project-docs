# L2 方案比较与分流决定：维修进度查询演练

**补录说明：**2026-10-31，在原演练后，根据[受理单](problem-intake.md)、[调查分析](investigation.md)及[原模拟输入 D1–D4](input.md)整理决策依据。没有补造真实立项评审、签字或新增业务决定。

## 需要作出的选择

目标是让员工在授权范围内得到可信进度和下一步，同时减少不必要的反复询问。方案应与原因匹配，保留不开发的可能；真实价值缺少测量数据，本次不虚构成本、收益或打分。

| 选项 | 适用条件 | 作用与限制 | 本案例处理 |
|---|---|---|---|
| 保持人工询问 | 低频且现有方式可以接受 | 无研发成本；信息仍依赖人工，需实际频次判断 | 保留为真实试点的对照，不编造其成本 |
| 操作指引/知识交接 | 已有入口可用，只是不知道如何查 | 可更快解决知识问题；不能补充缺失能力 | 真实调查优先核实；原模拟未提供旧入口 |
| 权限/配置或数据流程处理 | 查询能力已存在但受授权、配置或数据质量影响 | 修正对应问题；需要明确有权处理人和验证证据 | 作为非研发分支，当前无真实处理依据 |
| 新增只读查询能力 | 确有能力缺口并具备可信数据、授权与使用入口 | 需要研发及后续接入；API完成不等于员工可用性和业务收益已经验证 | 按原模拟 D1–D4 选为本次技术演练范围 |
| 主动通知、完整前端或新账号平台 | 另有明确业务需求和资源依据 | 扩大范围与责任 | 原模拟明确不做，不由本次分析新增 |

## 本次模拟决定与依据

沿用原输入，不新增批准：D1 选择只读查询接口；D2 只查本人且区分不存在/非法输入；D3 源故障明确反馈，恢复后重查，查询不改工单；D4 仅在本机隔离环境使用合成身份和数据验证。这个选择服务于本次模拟全链路演练；不能据此认定真实公司也必须开发。

决策责任标为“模拟业务角色”；真实业务负责人、预算、排期及审批均未确定。本轮用户授权模拟实现和隔离验证，不包含真实系统、生产发布或替业务签核。

## 交给 PRD 的内容

沿用 SIM-REPAIR-001 和唯一[PRD sim-1](prd.md)：本人查询、状态与下一步、身份及数据边界、非法/无数据/源故障处理和只读约束。用合成样本形成可验证的正常、边界、异常场景。调查中未取得的真实数据与权限不能写成已有能力。

本次只补充前置分析来源，未改变既有 FR-01/02、AC-01..07 或应用行为。真实项目进入正式需求基线前，应取得与所选方案有关的根因证据、业务规则和负责人确认；其余独立调查可以继续。后续若证据支持指导/配置/数据处理，应调整分流并保留原决定的变更记录。
