# 办公设备维修进度查询

> 产品版本：sim-1
> 状态：草稿
> 文档修订：r2，补充前置资料引用，业务规则保持 sim-1

## 业务背景与本次变化

模拟员工在报修后只能反复询问行政。本期增加只读查询接口，让员工凭已有调用身份和维修单号得到当前进度及下一步；身份不匹配时不暴露别人的明细。规则依据为[模拟业务输入](input.md)。本稿是唯一正式业务主文，需求身份 SIM-REPAIR-001；模拟决定不代表真实业务批准。

本期提供查询与健康检查，隔离环境使用合成身份及数据。报修、修改维修状态、通知、登录系统、前端页面和真实系统接入不在范围内。没有旧系统或迁移。本期结束位置为用户收到确定查询结果，效果改善另行观察，不预设收益数值。

## 业务需求与验收

### FR-01 查询自己的维修进度

状态：待确认
依据：SRC-01
原型：否

员工通过已有调用工具输入维修单号，获取其有权访问的工单；输入必须为 R- 后接三位数字。调用身份只取受控身份凭据，查询参数不得改变身份。R-100 的 alice 看到状态 repairing、设备 laptop 和下一步“等待维修完成”；不返回 owner 或内部记录。查询不创建、不修改任何维修单。

未提供或无效身份时提示需要有效身份；bob 查询 R-100 返回无明细拒绝，员工应使用自己的账号与单号，不能通过改参数绕过。合法单号 R-999 提示工单不存在，员工核对单号后可重新查询；空值或格式不合法提示输入错误。响应均不改变原工单。

#### AC-01 查询本人维修单

alice 查询 R-100，返回 repairing、laptop、等待维修完成，不包含 owner，原工单不变。

#### AC-02 缺少或无效身份

无身份或无效身份查询均拒绝访问，不泄露工单；取得有效身份后再查。

#### AC-03 越权与身份参数伪装

bob 查询 R-100，以及 bob 通过查询参数伪装 alice，均拒绝且不返回明细；使用本人账号和单号。

#### AC-04 无数据

alice 查询 R-999，明确不存在；核对单号后重查，不写入工单。

#### AC-05 非法输入边界

空值、R-10、R-1000、含非法字符的单号均为输入错误，不访问或改变工单。

### FR-02 故障反馈与恢复

状态：待确认
依据：SRC-01
原型：否

数据源不可用时，不显示缓存成功或编造维修状态，明确返回暂不可用；员工稍后对同一工单重新查询，行政/维护角色先恢复数据源。恢复后 R-100 仍为 repairing，原单号和数据不变。健康检查也应反映数据源不可用，避免上线检查只验证进程还活着。此只读接口没有写入结果不确定或重复提交问题。

#### AC-06 源故障与恢复

数据源故障时，查询 R-100 和检查健康状态均返回暂不可用，不伪报成功；维护恢复后同单查询成功。

#### AC-07 只读与重复操作

重复成功/失败查询、故障演练及恢复后，数据和原单号不变，结果不混入其他员工明细。适用 FR-01 与 FR-02。

## 数据与使用约束

维修单号、设备、归属身份、维修状态及下一步由数据源提供，本期不改变其含义。查询结果只返回单号、设备、状态、下一步；owner 只用于服务侧权限判断。数据源用固定合成记录演练，真实数据源和身份接入尚未实现。只读查询可反复执行，无状态转换。接口契约及隔离部署见[技术设计](design.md)。无业务页面变更，因此不交付页面线框或原型。

## 决策与交付

本次模拟输入中的关键规则已明确，无须向真实业务追问虚构参数。真实业务批准、真实身份与数据源接入、员工试读和效果测量仍未完成。模拟 UAT 可按 AC-01 至 AC-07 回放；它不能代替正式业务验收或生产批准。
