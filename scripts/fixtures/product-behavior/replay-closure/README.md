# 多轮回放与已知反例回归

这是人工／模型执行的补充回归组，沿用相邻目录的 cases.json 输入、continuations 和 checks 格式；尚未接入 product_behavior_eval.py 的标准 13 案例发布门槛，不能计为该门槛通过。园区维修是合成案例；结算复用既有模拟资料，不能冒充真实财务案例。

生成者只接收冻结 Skill、当前已释放的原始输入、获准资料和自己的既往产物。先把本轮输入复制到独立执行目录；不要向生成者提供本目录 README、cases.json 的 checks、评审报告、参考答案或后续输入。每轮实际回复与产物保存完成后再释放下一轮，保留不可变快照和输入、Skill、产物哈希。

评审者先根据全部原始资料独立形成验收，再阅读实际成品；随后可用 cases.json 中的已知反例做定向回归。后者必须标记“已知反例复验”，不能称为新盲测。原型采用仓库现有 product_browser.mjs 无界面入口，走实际页面控件；测试脚本、浏览器回执和截图绑定同一份成品。修复前保留失败证据，修复后重跑受影响旅程并做独立复验；没有浏览器或无法独立评审时如实标记未验证。

真实财务回放另由本地提供原始 Word、授权代码快照和按时间排序的原用户输入，逐轮释放；私有材料及历史输出不入此目录。记录代码快照是否等同历史运行环境，不能用模拟结算输入替代真实来源后声称已回放原案。

报告分别列出首轮发现、修复内容、复验结果和仍未验证范围，提供实际 Markdown PRD。有限案例通过不表示未来稳定通过；这个公开案例在后续运行中属于已知回归，评估泛化仍需另选未提前暴露的需求。
