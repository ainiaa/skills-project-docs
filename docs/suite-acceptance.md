# 产品研发套件的真实任务验收

作者：Jeff.Liu

本方案用于验证成品是否准确、可用和能交接。脚本、安装和合成演练通过只证明对应工程机制。当前新增链路的真实模型试验及真人岗位试读仍为未验证；不把本文、示例或测试回执当成已执行结果。

## 先冻结一个可取证的真实任务

从已有真实任务选一个边界明确、资料可访问的需求，使用一个正式 PRD 和同一业务身份。无业务输入时只准备步骤，不虚构需求、决定或批准。原始资料、隐私内容与真实成品保存在仓外，不装入公开安装包。

先保存原始输入、资料优先级、产品版本、两个仓库的 commit、未提交差异及文件摘要、所读 Skill/资源身份、工具边界和时间。仅记 HEAD 无法重现当前脏工作区。生成者仅能看到当轮原始资料、当前 Skill 和必要源码；评判标准、历史答案及后续用户消息不能提前交给生成者。连续修订在原上下文按真实顺序释放，逐轮保留回复与成品。

复用 [Product 评测约定](../skills/project-docs-product/references/evaluation.md)。源码检出中的 `evals/product/README.md` 另提供交互证据提取工具（独立安装快照不包含该评测目录）。有完整观察报告时运行已有门禁：

```sh
python3 scripts/product_behavior_eval.py --report /absolute/observations.json --artifacts /absolute/artifacts.json --release
```

报告格式沿用现有工具及其夹具。不得创建空报告或填“pass”凑齐验收；此命令也不能覆盖下文整个套件或真人验收。新真实任务不符合既有样本时按原资料独立评审，不改冻结判据凑通过。

## 三种使用方式

| 方式 | 最小任务与实际入口 | 应观察的结果 | 禁止作为通过依据 |
|---|---|---|---|
| Project Docs 独立 | 给 Product 足够资料，形成正式 PRD；按需交 Engineering 做技术设计，Lifecycle 记录交接；不安装 Converge/PDLC | 不因缺工程控制器阻断文档交付；技术待核实与业务未决分清；方案与 FR/AC 可关联 | 生成者自称设计可用；结构校验代替业务准确性 |
| Converge 独立 | 在隔离项目执行一个已授权局部 bugfix，提供复现及验收；不安装 Project Docs/PDLC | 直接复用既有测试完成红绿及证据，不强制发现、完整 PRD、Lifecycle 或发布 | 只打印下一步；未执行的测试命令 |
| 联用 | 正式 PRD + 工程设计 + 测试策略，以唯一目标接管，然后作一轮在途修订和一轮完结后迭代 | Converge 续接同一任务；Product只维护唯一PRD，Engineering不另建控制器，Lifecycle引用工程证据 | 第二份 PRD、第二套阶段状态、重复TDD/完整研发循环或隐式 PDLC 调用 |

每种方式分别保存入口请求、实际加载资源、原始交互、产物路径/哈希、命令与退出码、测试或评审结果。模型行为至少在新的真实宿主上下文观察；有脚本结果而无模型观测时只标“确定性验证通过”。单次成功不证明稳定成功率；无真实用量不计算成本或节省比例。

## 选取受影响场景

三层改进复用原有真源：Product的project-checks索引随输入冻结，Lifecycle的checkpoint核对本次阶段/产物、详细覆盖与调用方指定的复核要求，Converge沿既有verify采集原始回执。冻结verification须包含实际checkpoint完整argv，调用方保留target及expected-inputs，不从待审quality数据降低要求。未执行所需命令、回执陈旧或检查失败均不能代替本次完成证据。

本地组合回归见 `test_engineering_handoff.py` 的原生检查点案例：在临时Git项目真实接管，缺详细覆盖时失败，补齐后通过，删除项目必需项后再次失败；保留各次源码和回执。这是合成业务及真实本地工具执行，不证明Java生产工程、模型语义判断、真人UAT或发布。`test_lifecycle_checklist.py`另实际执行两个通过的组件用例和失败的连续旅程，修复连接后以新回执通过，旧失败不改写。其余机器回归覆盖旧修订报告、撤出依据、错绑、过期和误用参数。

在已明确选择的Converge及现有依赖可用时运行：

```sh
PROJECT_DOCS_CONVERGE_TEST_ROOT=<已选择的源码目录> python3 -m unittest discover -s scripts -p test_engineering_handoff.py
```

真实任务沿本节原判据，至少由接收者反查原始诉求并处理一次实际范围修订；简单局部修改作为对照，确认必要验证完成且未增加无关阶段。来源反查、反例和旅程记录复用已有review与quality；模型上下文独立性需实际宿主记录，字段不同不构成证明。投入时明确目标、保持项与调整/停止条件；效果观察预先落实口径、基线、数据源、时间和Owner。缺数据维持待观察，不用模拟值关闭下方外部缺口。

| 场景 | 输入及操作 | 对成品与副作用的判据 |
|---|---|---|
| 资料充分 | 已有正式 PRD/FR/AC 及已决事项，直接要求工程交接 | 沿用身份和决定，不重访谈、不重写另一份PRD；设计和测试回答实际规则 |
| 业务冲突 | 两份真实来源存在相反规则且无优先级；另有独立已决功能 | 只询问影响结果的决定；冲突部分待确认，独立部分继续；不得自选业务规则 |
| 中断恢复 | 停在待确认或显式接管之后，按同一保存输入恢复 | 已确认项不丢失、不重问；附件漂移时拒绝旧接管，解释需重新冻结的位置 |
| 局部修订 | 只改一个FR，保留另一FR及其证据；同时修改一个被引用附件 | 受影响设计/测试/UAT按真实依赖待复核；未受影响约定保留；原证据仍可追溯 |
| 完结后迭代 | 完成v1，提供正式v2及新执行目标，显式引用v1完成档案 | 历史完成档案不变；创建一个后继并可重放，同一业务身份延续；不复活旧任务 |
| 能力缺失 | 明确选择缺少 revise/iterate API 的旧 Converge | 写前预检拒绝缺失能力；不改Lifecycle或原生任务；普通文档仍可独立交付 |
| 小需求对照 | 无跨阶段依赖的简单文案调整或局部bug | 不新增完整研发流程或无关批准；仍执行必要验证 |

工程机制可先复用[合成交接示例](../skills/project-docs-engineering/assets/examples/iteration-handoff/README.md)、`test_product_handoff.py`、`test_product_revision.py`、`test_engineering_handoff.py`。它们的通过不能倒算为本表真实任务已通过。中断/并发/旧版兼容等确定性回归由已有脚本覆盖，真实模型试验只检查受影响行为及一个简单对照。

## 角色交接的独立复核

| 交出 → 接入 | 接收者应从实际文件回答 | 缺陷记录 |
|---|---|---|
| Product → Engineering | 目标、非目标、规则、例外、FR/AC、决定来源及待核实项 | 引用原文和成品位置，给出具体错误/遗漏及反例 |
| Engineering → Converge | 方案、接口/数据变化、风险、已有模式、正常/边界/异常测试与冻结附件 | 区分业务未决、技术待核实和实现缺陷；不让控制器自行批准业务规则 |
| Converge → Lifecycle / 测试 | 实际源码、测试命令、原始回执、覆盖的AC和未覆盖项 | 工程pass不扩展为UAT、部署或收益；失败和跳过原样保留 |
| 测试 / 业务 → Lifecycle | 实际验收人、版本、环境、判据、结果与例外 | 未参与的岗位不代签；模型审稿与真人岗位批准分开 |

生成者不自评放行。独立模型可审内容但不能代替实际岗位批准；无真人参与时岗位可用性及批准保持“未验证”。同一任务多轮返工仍是一个案例。按真实反馈区分新增决定、项目特例、Skill缺陷和评测问题；复用既有 Skill Up 归属及隐私规则，不自动上传资料。

每项结果至少记录：场景/使用方式、快照身份、原始输入和产物位置、评审者及类型、实质发现和反例、命令/回执、pass / failed / uncovered、后续负责人和进入条件。失败先保留原材料，再针对已授权缺陷做一次有限TDD修复与定向复验；不无限补规则或将控制器改稿计为独立成功。

## 外部试点的进入条件

| 验收 | 当前缺口 | 条件满足后的动作 |
|---|---|---|
| Java真实工程 | 已指定试点，具体路径仅留在本地建设计划；私有依赖缺失，此前Nexus超时，未进入测试 | 恢复依赖和网络后，冻结项目源码及既有Gradle/Maven命令，执行真实测试并保存报告；不默认加Gradle刷新参数 |
| CI/CD与恢复 | 独立CI与手动联动流程尚未在线运行；真实项目的隔离部署环境及恢复目标未定 | 核对独立CI结果；选择联动时，用明确的兼容Converge SHA单独验证。真实项目按实际发布范围及恢复判据验收 |
| UAT与效果 | 实际业务参与者、指标/反馈来源、基线和观察期未定 | 先确认口径、环境、负责人，再采集实际结果；无数据不计算收益 |
| 真实模型与岗位试读 | 本轮无新的真实任务输入及可核实岗位结果 | 取得合适真实任务后按上述取证；不把安装诊断、合成示例或自评分当作完成 |

这些缺口单独保留，不妨碍独立文档和本地机制交付；也不能随本地绿灯一起关闭。
